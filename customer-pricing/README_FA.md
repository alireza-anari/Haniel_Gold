# HANI-EL GOLD — مینی‌اپ عمومی مشاهده قیمت

این سرویس یک Telegram Mini App عمومی و مستقل برای مشاهده قیمت محصولات است. پنل مدیریت خصوصی باقی می‌ماند و هر دو Worker به همان D1 متصل می‌شوند.

## رفتار قطعی قیمت‌گذاری

- نرخ طلای ۱۸ عیار از Servix هر ۳۰ دقیقه دریافت می‌شود.
- نرخ در جدول مشترک `gold_market_state` نگهداری می‌شود؛ جدول مستقل یا کش دوم برای نرخ ساخته نمی‌شود.
- اولین نرخ و تغییرات بزرگ تا بررسی مالک در حالت مسدود می‌مانند.
- پس از تأیید مالک و تعیین سقف تغییر خودکار، تغییرات کوچک‌تر یا مساوی آن سقف خودکار پذیرفته می‌شوند.
- اگر نرخ منقضی، مسدود یا نامعتبر باشد، مشتری قیمت نمی‌بیند.
- قیمت محصول فقط هنگام درخواست مشتری محاسبه می‌شود؛ قیمت محصول در D1 ذخیره نمی‌شود و Cron هیچ قیمت محصولی را محاسبه یا بازنویسی نمی‌کند.
- فرمول عمومی دقیقاً همان فرمول تأییدشده پنل فروش است: طلای خام + اجرت + سود + متعلقات − تخفیف. مالیات یا هزینه جدیدی بدون سیاست تأییدشده به آن اضافه نمی‌شود.
- مقادیر مالی در D1 به ریال نگهداری می‌شوند و رابط مشتری مبلغ را به تومان نمایش می‌دهد.

## ساختار تنظیمات عمومی محصول

در ساختار Mini App مدیریت، جدول `products` اطلاعات محصول و داده‌های خرید را نگهداری می‌کند؛ مقادیر `labor_pct`، `profit_pct`، `accessories` و `discount` در جدول `sales` سوابق تاریخی هر فروش هستند و به‌تنهایی تنظیم جاری محصول محسوب نمی‌شوند.

Migration شماره ۳ جدول مستقل `product_public_pricing` را می‌سازد. هیچ سابقه فروشی به‌عنوان تنظیم جاری در دیتابیس کپی نمی‌شود. در پنل خصوصی، آخرین مقادیر فروش غیرابطال‌شده فقط به‌صورت پیشنهاد فرم نمایش داده می‌شوند؛ مالک باید آن‌ها را بازبینی و ذخیره کند. اگر سابقه فروش وجود نداشته باشد، اجرت خرید صرفاً پیشنهاد اولیه است و درصد سود فروش باید تعیین شود.

فعال‌سازی نمایش عمومی، ذخیره تنظیمات قیمت و تأیید سیاست نرخ فقط برای مالک اصلی انجام می‌شود. دسترسی نقش‌های قبلی مدیر، فروشنده و مشاهده‌گر برای سایر بخش‌های پنل حفظ شده است.

## فایل‌ها

- `src/index.js`: Worker عمومی، API فقط‌خواندنی و Cron نرخ
- `src/pricing.js`: محاسبه قیمت با همان موتور مالی پنل مدیریت و تبدیل ریال به تومان
- `public/`: رابط فارسی و RTL مناسب Telegram Mini App
- `wrangler.toml`: تنظیمات Worker مشتری و D1
- `../telegram-miniapp/db/migrations/0003_public_pricing.sql`: جدول تنظیمات قیمت عمومی
- `../telegram-miniapp/db/migrations/0004_gold_market_policy.sql`: جداول نرخ، ثبت رویداد و سیاست مستقل نرخ
- `scripts/add-price-buttons.mjs`: افزودن دکمه مشاهده قیمت به پست‌های کانال

## محیط Cloudflare فعلی

در حساب Cloudflare متصل، دیتابیس قابل شناسایی HANI-EL این است:

- نام: `haniel-gold-miniapp-qa-20261114`
- شناسه: `ac6ed841-fe6e-412a-9d33-b3f3a497b1ef`
- محیط: QA

تنظیمات فعلی هر دو Worker عمداً به همین D1 آزمایشی اشاره می‌کنند. این دیتابیس هنگام بررسی، جدول‌های پایه پنل مدیریت را داشت اما هیچ محصول، فروش، کاربر یا تصویری در آن ثبت نشده بود. در حساب متصل، Worker یا Pages فعال HANI-EL و D1 تولیدی قابل شناسایی نبود؛ بنابراین این تنظیمات را Production تلقی نکن.

## پیش‌نیازهای استقرار QA

1. Wrangler نسخه ۴ را نصب و به حساب Cloudflare مربوط به HANI-EL متصل کن:
   ```bash
   npx wrangler@4 login
   npx wrangler@4 whoami
   npx wrangler@4 d1 list
   ```
2. مطمئن شو دیتابیس `haniel-gold-miniapp-qa-20261114` در همان حساب انتخاب شده است.
3. قبل از هر تغییر D1، از دیتابیس خروجی پشتیبان بگیر.
4. این Workerها فقط برای QA هستند؛ شناسه D1 تولیدی هنوز در این تنظیمات وجود ندارد.

## اجرای Migration روی D1 آزمایشی

از ریشه مخزن، هر Migration را یک‌بار و به ترتیب اجرا کن:

```bash
npx wrangler@4 d1 execute haniel-gold-miniapp-qa-20261114 --remote \
  --file=telegram-miniapp/db/migrations/0003_public_pricing.sql \
  --config=customer-pricing/wrangler.toml

npx wrangler@4 d1 execute haniel-gold-miniapp-qa-20261114 --remote \
  --file=telegram-miniapp/db/migrations/0004_gold_market_policy.sql \
  --config=customer-pricing/wrangler.toml
```

این Migrationها فقط جدول‌ها و ایندکس‌ها را می‌سازند و هیچ ردیفی در جدول محصولات، فروش، نرخ یا تنظیمات درج نمی‌کنند. ردیف‌های singleton نرخ و سیاست، در اولین اجرای زمان‌بندی یا بازشدن پنل مالک، با حالت مسدود و تأییدنشده ایجاد می‌شوند. هیچ محصول یا سابقه فروشی درج، حذف یا بازنویسی نمی‌شود.

## استقرار Worker عمومی مشتری

```bash
npx wrangler@4 secret put SERVIX_API_KEY --config=customer-pricing/wrangler.toml
npx wrangler@4 deploy --config=customer-pricing/wrangler.toml
```

کلید Servix را فقط در prompt مخفی Wrangler وارد کن؛ آن را در GitHub یا فایل عمومی قرار نده. این Worker به توکن ربات تلگرام نیاز ندارد. نام Worker در تنظیمات فعلی `haniel-gold-customer-pricing-qa` است.

پس از Deploy، آدرس واقعی `workers.dev` را از خروجی Wrangler بردار. Cron هر ۳۰ دقیقه اجرا می‌شود. تا زمانی که نرخ معتبر و تأییدشده وجود نداشته باشد، API قیمت نمایش نمی‌دهد.

## استقرار پنل مدیریت QA

از پوشه `telegram-miniapp`:

```bash
npm install
npm run check
npm test
npm run deploy
```

تنظیمات `cloudflare.config.ts` در این شاخه به Worker آزمایشی `haniel-gold-manager-qa` و همان D1 QA متصل است. Secretهای `BOT_TOKEN` و `OWNER_TELEGRAM_ID` را فقط از طریق ابزار Deploy و Secret Store تنظیم کن. هیچ‌کدام نباید وارد GitHub شوند.

## تأیید نرخ و سیاست خودکار

1. مالک در پنل مدیریت، بخش «نرخ طلا» را باز می‌کند.
2. اولین نرخ دریافتی Servix به‌صورت پیشنهادی و مسدود نمایش داده می‌شود.
3. مالک پس از بررسی، نرخ اولیه را تأیید می‌کند.
4. مالک سقف تغییر خودکار نرخ را تعیین و صریحاً تأیید می‌کند.
5. تغییرات بعدی در محدوده سقف، خودکار پذیرفته می‌شوند؛ تغییر بزرگ‌تر دوباره به تأیید مالک نیاز دارد.

این سقف فقط سیاست پذیرش تغییر نرخ است و هیچ درصد مالیات یا مبلغی به فرمول قیمت محصول اضافه نمی‌کند.

## تنظیم Mini App در تلگرام

در BotFather برای ربات مدیریت، یک Direct Mini App با short name مانند `pricing` بساز و URL آن را روی آدرس واقعی Worker عمومی QA قرار بده.

قالب لینک محصول:

```text
https://t.me/<bot_username>/pricing?startapp=product_15&mode=compact
```

عدد انتهایی شناسه واقعی محصول در D1 است. پارامتر `mode=compact` برای نمایش نیم‌صفحه استفاده می‌شود.

## افزودن دکمه به پست‌های کانال

ربات باید در کانال ادمین و دارای مجوز ویرایش پیام‌ها باشد. در فایل JSON برای هر پست، شناسه پیام، شناسه محصول و تصویر کامل صفحه‌کلید فعلی را قرار بده. اگر پست دکمه‌ای ندارد، حتماً `existing_keyboard: []` بنویس. ابزار بدون snapshot صریح صفحه‌کلید اجرا نمی‌شود و دکمه تکراری را دوباره اضافه نمی‌کند. نمونه در `scripts/posts.example.json` است.

متغیرهای محیطی:

- `BOT_TOKEN`: توکن ربات؛ فقط در محیط محلی خودت
- `CHANNEL_ID`: مانند `@channelname` یا شناسه عددی کانال خصوصی
- `PRICE_APP_LINK`: مانند `https://t.me/<bot_username>/pricing`

ابتدا Dry Run:

```bash
cd customer-pricing
BOT_TOKEN='...' CHANNEL_ID='@channelname' \
PRICE_APP_LINK='https://t.me/<bot_username>/pricing' DRY_RUN=1 \
node scripts/add-price-buttons.mjs scripts/posts.json
```

پس از بررسی لینک‌ها، `DRY_RUN` را حذف کن و فرمان را اجرا کن. Telegram Bot API در `editMessageReplyMarkup` صفحه‌کلید قبلی پیام را جایگزین می‌کند؛ آرایه `existing_keyboard` باید تمام دکمه‌های قبلی را در بر بگیرد تا حذف نشوند. اجرای دوباره ابزار برای همان لینک، دکمه تکراری ایجاد نمی‌کند.

## امنیت و حریم خصوصی

- Worker عمومی فقط شناسه، SKU، نام، وزن، وضعیت موجودی، تصویر مجاز و اجزای مجاز قیمت را برمی‌گرداند.
- نرخ خرید، اجرت خرید، تأمین‌کننده، یادداشت داخلی، نام مشتری، بهای خرید و سود خالص در Query عمومی خوانده یا پاسخ داده نمی‌شوند.
- تصویر فقط برای محصولی قابل دریافت است که نمایش عمومی آن فعال باشد.
- API عمومی فقط GET دارد؛ مسیر نوشتن محصول یا فروش در این Worker وجود ندارد.
- تنظیمات قیمت و سیاست نرخ فقط از پنل خصوصی و پس از احراز هویت مالک قابل تغییر هستند.
- نرخ خرید و قیمت محاسبه‌شده محصول در این Mini App به‌صورت دوره‌ای ذخیره نمی‌شوند؛ فقط نرخ بازار و رویدادهای کنترل آن نگهداری می‌شوند.
