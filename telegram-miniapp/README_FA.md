# HANI-EL GOLD — Telegram Mini App (Cloudflare)

**نسخه 1.0 آزمایشی | ربات:** [@Hani_El_manager_bot](https://t.me/Hani_El_manager_bot)  
**میزبانی:** Cloudflare Workers + D1 + R2، با `workers.dev`  
**وضعیت:** کد و آزمون‌های پایه آماده هستند؛ **روی حساب Cloudflare کاربر مستقر یا از نظر build ابری تأیید نشده‌اند**.

> ⚠️ این نسخه مخصوص Cloudflare است. نسخهٔ قدیمی Node.js/SQLite را مستقیم روی Workers آپلود نکنید. برای اطلاعات مالی واقعی، ابتدا با کپی پشتیبان اکسل و داده‌های آزمایشی بررسی کنید.

## قابلیت‌های موجود در این نسخه

- داشبورد موجودی و فروش، محصولات، ثبت و ابطال فروش، قیمت‌گذاری دستی با نرخ روز طلا
- نمایش و ویرایش محصولات، گالری تصاویر خصوصی در R2
- نقش‌های مالک / مدیر / فروشنده / مشاهده‌گر؛ بررسی `Telegram.WebApp.initData` توسط HMAC سرور
- ورود Excel با پیش‌نمایش تعداد تغییرات و مغایرت‌ها؛ کنترل شناسه ثابت کالا و جلوگیری از فروش/کسر موجودی تکراری
- صدور فایل Excel جدید از محصولات و فروش‌های ثبت‌شده؛ گزارش‌های پایه و ثبت تاریخچه عملیات
- رابط فارسی راست‌به‌چپ با لوگوی رسمی HANI-EL GOLD

## مهم‌ترین محدودیت نسخه اول

**واردسازی و خروجی فعلاً فقط دو شیت «موجودی» و «فروش» را پشتیبانی می‌کند.** سه شیت دیگر فایل اصلی («متعلقات»، صندوق طلا و تأمین‌کننده) نه به دیتابیس منتقل می‌شوند، نه در فایل خروجی جدید حفظ می‌شوند. **به هیچ وجه خروجی جدید را جایگزین بی‌برگشت فایل حسابداری اصلی نکنید.** همیشه از فایل اصلی پشتیبان مستقل نگه دارید. فایل اکسل اصلی شما داخل بسته پروژه قرار نگرفته است.

- با Import، فایل اکسل روی رایانه یا گوشی به‌صورت خودکار تغییر نمی‌کند؛ برای گرفتن نسخه جدید، `خروجی Excel` بزنید.
- حذف یک ردیف محصول از Excel در مینی‌اپ آن را پاک نمی‌کند؛ تغییر سطرهای فروش قدیمی با شناسه تغییر‌یافته می‌تواند باعث مغایرت شود. برای همگام‌سازی مطمئن از آخرین خروجی مینی‌اپ استفاده کنید.
- تاریخ فروش شمسی به‌صورت متنی نگهداری می‌شود. نرخ روز طلا دستی است؛ نرخ لحظه‌ای آنلاین ندارد.
- این پروژه فعلاً فاکتور رسمی چاپی، حسابداری کامل صندوق طلا، مالیات، بکاپ خودکار و گردش‌کار پیچیده انبار ندارد.
- نسخه فعلی از CLI جدید Cloudflare (`cf`) استفاده می‌کند که هنوز در **open beta** است و ممکن است تغییر کند.

## 1. آماده‌سازی کامپیوتر و حساب Cloudflare

۱. از https://nodejs.org نسخه Node.js **22.18 یا جدیدتر** نصب کن و از باز بودن ترمینال/PowerShell مطمئن شو.  
۲. وارد **حساب دوم** Cloudflare خودت شو.  
۳. فایل ZIP این پروژه را Extract کن؛ لازم نیست پروژه یا حساب را به ChatGPT وصل کنی.

### منابع ابری

در داشبورد Cloudflare روی **همان حساب دوم** دو منبع بساز:

| محصول | نام دقیق | کاربرد |
|---|---|---|
| D1 database | `haniel-gold-db` | محصولات، فروش، کاربران و سابقه تغییرات |
| R2 bucket | `haniel-gold-product-images` | عکس‌های کالا |

در صورت فعال‌نبودن R2، داشبورد ممکن است فعال‌سازی و ثبت روش پرداخت بخواهد؛ قبل از تأیید شرایط و قیمت را بررسی کن. **دسترسی عمومی برای bucket فعال نکن**؛ برنامه تصویرها را از مسیر محافظت‌شده ارائه می‌کند.

**ساخت جداول:** در D1 → پایگاه داده `haniel-gold-db` → Console/SQL editor، محتوای کامل فایل `db/schema.sql` را اجرا کن. اگر SQL editor فقط یک statement می‌پذیرد، دستورها را به ترتیب اجرا کن. در انتها جداول `products`, `sales`, `users`, `images`, `audit`, `meta`, `imports` باید وجود داشته باشند.

## 2. گرفتن اطلاعات ورود مالک (فقط نزد خودت)

- از BotFather، توکن موجود برای `@Hani_El_manager_bot` را دریافت کن.
- شناسه عددی **حساب تلگرام خودت** را پیدا کن؛ منظور یوزرنیم یا شماره تلفن نیست. از روشی که به آن اعتماد داری استفاده کن.
- از فایل `secrets.local.example.json` یک کپی به نام **`secrets.local.json`** بساز. دو جای‌خالی را فقط روی دستگاه خودت پر کن:

```json
{
  "BOT_TOKEN": "توکن محرمانه صادرشده توسط BotFather",
  "OWNER_TELEGRAM_ID": "شناسه عددی حساب تلگرام مالک"
}
```

**این فایل را در GitHub، فضای عمومی یا چت منتشر نکن.** `.gitignore` فایل واقعی secrets را نادیده می‌گیرد.

## 3. نصب، بررسی و انتشار با Cloudflare CLI

ترمینال یا PowerShell را **در پوشهٔ استخراج‌شده پروژه** باز کن و به‌ترتیب اجرا کن:

```sh
node --version
npm install
npm test
npm run check
npx cf auth login
npx cf auth whoami
npx cf deploy --dry-run
npx cf deploy --secrets-file ./secrets.local.json
```

وقتی صفحه لاگین باز شد، **حساب دوم مورد نظر** را انتخاب کن. اگر بیش از یک حساب در دسترس باشد، در مرحله انتشار حتماً حساب درست را انتخاب کن. اگر محیط کار اشتباه بود، از داشبورد Cloudflare `Account ID` حساب دوم را بردار و طبق مستندات CLI مقدار `CLOUDFLARE_ACCOUNT_ID` را برای ترمینال خودت تنظیم کن.

اگر هنگام `deploy` نام‌های D1/R2 resolve نشدند، در تنظیمات Worker bindingهای `DB` و `PHOTOS` را بررسی کن و مطمئن شو منبع مربوطه در همان حساب است. در پایان فرمان، Cloudflare آدرس **واقعی** `https://...workers.dev` را نمایش می‌دهد. آدرس را دقیقاً کپی کن؛ ما نمی‌توانیم نام زیردامنه حساب تو را از قبل حدس بزنیم.

> نکته: برای انتشارهای بعدی نیز `npx cf deploy --secrets-file ./secrets.local.json` را اجرا کن تا Secretهای لازم همیشه به نسخه منتشرشده ارسال شوند.

### راه‌های خطایابی اولیه

- اگر هنگام نصب خطای **Node version** دیدی، نسخه Node.js را به 22.18+ ارتقا بده.
- اگر ساخت/Deploy از `@cloudflare/vite-plugin` یا `cf` ایراد گرفت، نسخه package را تغییر نده مگر با بررسی راهنمای نسخه فعلی Cloudflare؛ این CLI در حالت بتاست.
- اگر API خطای کمبود جدول می‌دهد، `db/schema.sql` را در D1 **production** اجرا کن، نه فقط در محیط محلی.
- اگر صفحه باز می‌شود ولی خطای ورود داری، از داخل **منوی ربات تلگرام** باز کن. بازکردن مستقیم URL در Chrome/Firefox داده ورود Telegram WebApp را ارسال نمی‌کند.
- اگر ورود تو «عدم دسترسی» می‌دهد، `OWNER_TELEGRAM_ID` باید برابر **ID عددی همان حساب تلگرام بازکننده مینی‌اپ** باشد.

## 4. وصل‌کردن ربات به آدرس مینی‌اپ

در Telegram، به ربات `@BotFather` برو:

1. فرمان `/setmenubutton` را ارسال کن (یا Bot Settings → Menu Button).
2. ربات `@Hani_El_manager_bot` را انتخاب کن.
3. برای متن دکمه بنویس: **مدیریت هانی‌ال**.
4. آدرس HTTPS واقعی و کامل `https://...workers.dev` را که Cloudflare پس از انتشار داده، وارد کن.
5. چت ربات خودت را باز کن و روی دکمه جدید بزن.

برای این نسخه **Webhook لازم نیست**؛ مینی‌اپ با فشار دکمه Menu باز می‌شود و مستقیم به API Worker وصل می‌شود. اگر در آینده فرمان‌های پاسخ‌گوی ربات، اعلان یا دریافت فایل از چت بخواهیم، Webhook جداگانه می‌سازیم.

## 5. فعال‌کردن همکاران

- اولین‌بار به‌عنوان مالک وارد شو؛ دسترسی مالک از `OWNER_TELEGRAM_ID` ایجاد می‌شود.
- در بخش «تیم»، شناسه عددی تلگرام و نقش هر همکار را وارد کن.
- نقش‌ها:
  - **owner**: مدیریت کامل و گزارش‌ها
  - **manager**: محصولات، واردسازی Excel، گزارش سود، فروش و مدیریت تصاویر
  - **sales**: محصولات عمومی، ثبت فروش و محاسبه قیمت؛ بدون دیدن بهای خرید و سود داخلی
  - **viewer**: مشاهده مشخصات مجاز و موجودی محصولات
- همکار بدون تعریف نقش در D1 نمی‌تواند به داده‌های خصوصی وارد شود. **احراز هویت و مجوزها سمت Worker انجام می‌شوند، نه فقط با پنهان‌کردن دکمه‌ها.**

## 6. واردکردن اکسل

1. **از فایل `Haniel Invoice.xlsx` کپی پشتیبان بگیر.**
2. داخل مینی‌اپ، بخش `اکسل` → `ورود اکسل` را باز و فایل `.xlsx` را انتخاب کن.
3. پیش‌نمایش شمار کالاهای جدید/تغییریافته و فروش‌ها را ببین؛ اگر `مغایرت` یا `خطا` نشان داده شد، واردکردن را تأیید نکن و منبع را اصلاح کن.
4. پس از تأیید، محصولات و فروش‌های پشتیبانی‌شده در D1 ثبت می‌شوند.
5. برای انتقال اطلاعات جدید از مینی‌اپ به اکسل، `خروجی Excel` را بزن؛ **فایل جدید** دانلود می‌شود، فایل قبلی روی رایانه overwrite نمی‌شود.

**کنترل‌های مهم:** شناسه محصول مستقل از نام، بررسی تعداد موجودی و جلوگیری از تکرار همان فروش، پیش‌نمایش قبل از Commit، کنترل نسخه دیتابیس هنگام واردکردن.

## 7. بررسی پیش از ورود اطلاعات واقعی

- به‌عنوان مالک وارد شو و یک کالای **آزمایشی** بساز، تصویر آپلود کن، با نرخ آزمایشی فروش آزمایشی ثبت کن و آن را ابطال کن.
- یک همکار `sales` و یک همکار `viewer` تعریف کن و مجوزهایشان را از خود حساب‌های تلگرام آن‌ها بررسی کن.
- **اول یک کپی** از فایل اکسل را Import کن. ارزش موجودی، وزن و شمار فروش را با فایل خودت مقایسه کن.
- سپس Export بگیر و مقادیر و فرمول‌های فروش را کنترل کن.
- بکاپ گیری دوره‌ای D1 و R2، مدیریت گردش مالی و حفظ سه شیت پشتیبانی‌نشده، پیش از استفاده اصلی نیازمند برنامه عملیاتی جداست.

## آزمایش‌های انجام‌شده در محیط ساخت

- `node --check` کدهای JS: موفق
- تست WebCrypto برای امضای تلگرام، و تست محاسبات مالی: موفق (۷ تست)
- خواندن فایل اکسل واقعی آپلودشده با JSZip: ۳۶ محصول، ۵ فروش، بدون خطا و مغایرت در بارگذاری اولیه آزمایشی
- ساخت و بازخوانی خروجی نمونه XLSX: موفق

**انجام‌نشده:** نصب npm/Cloudflare build در محیط ساخت، تست عملی D1/R2 روی اکانت تو، انتشار روی workers.dev، تست نهایی روی Telegram گوشی. بنابراین وضعیت فعلی یک **نسخهٔ اولیه برای استقرار و آزمون** است، نه محصول Production تأییدشده.
