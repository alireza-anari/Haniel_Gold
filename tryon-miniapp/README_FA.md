# HANI-EL GOLD — Customer Virtual Try-On (completely separate from private Manager)

## تصمیم معماری (پس از اصلاح مالک)

- **مینی‌اپ مدیریت تلگرام، خصوصی و مخصوص نقش‌های مجاز** باقی می‌ماند. این شاخه نه کد `telegram-miniapp` را تغییر می‌دهد، نه توکن یا مسیرهای ورود مدیریت را.
- **مینی‌اپ مشتری** در پوشه مستقل `tryon-miniapp/`، با Worker مستقل `haniel-gold-tryon` اجرا می‌شود. در آن هیچ داشبورد مدیریت، API فروش، اطلاعات مالی، پنل کاربران یا امکان ورود به مینی‌اپ مدیر وجود ندارد.
- دیتابیس مشتری **حتی از نظر Binding** از D1 خصوصی مدیریت جدا است. فقط پایگاه داده عمومی و حداقلی `haniel-tryon-public` / `haniel-tryon-public-test` به Worker مشتری وصل می‌شود.
- تنها منبع معتبر برای SKU و نام محصول، دیتابیس مدیریت `haniel-gold-db` است، اما **دسترسی مستقیم مشتری به آن ممنوع است**.
- مسیر انتقال در آینده: سرویس داخلی و جداگانه `tryon-sync/`، فقط SKUهای صراحتاً تأییدشده مالک و تصویر با شناسه انتخاب‌شده را به کاتالوگ عمومی انتقال می‌دهد. این Worker سرویس عمومی ندارد، `fetch` آن همواره 404 است و `SYNC_ENABLED` پیش‌فرض 0 دارد.

## مشتری دقیقاً چه می‌بیند؟

- ورود با لینک اختصاصی `startapp=sku_HG-XXXXXXXXXXXX`
- دریافت نام/نوع محصول و تصویر شفاف تأییدشده از `GET /api/v1/products/:sku` و `GET /api/v1/assets/:sku` روی **Worker مشتری**
- آپلود عکس شخصی **فقط داخل دستگاه کاربر** (Canvas/MediaPipe)، امکان جابه‌جایی، تغییر مقیاس و ذخیره
- فعلاً پرو زنده، AI مولد پولی، فروشگاه غیرفعال و API مدیریت به مشتری متصل نیستند.

## رفتار امنیتی

- تمام داده‌های مشتری از جدول مجزای `tryon_public_catalog` خوانده می‌شوند. این جدول فقط داده تأییدشده و بدون قیمت خرید/اجرت/تأمین‌کننده/فروش دارد.
- دسترسی عمومی فقط `GET` است؛ APIهای داخلی مدیریت روی Worker مشتری وجود ندارند.
- هر محصول ابتدا باید به‌صورت مستقل از نظر شکل واقعی، تصویر شفاف، نام و مطابقت SKU بررسی شود. هیچ کدام از 36 محصول مدیریت خودکار برای مشتری منتشر نمی‌شوند.
- تصاویر مشتری در سرور ذخیره نمی‌شود. آپلود تصویر فقط برای رندر محلی است.
- اگر عکس استاندارد نباشد یا برش محصول دقیق نباشد، تصویر نهایی **تضمین‌شده نیست** و باید آزمون بصری شود.
- `TRYON_PUBLIC_ENABLED` برای Production پیش‌فرض 0 است و محیط Production با تنظیم فعلی تا ساخت DB مستقل قابل استقرار نیست.
- سرویس sync فقط در محیط مجاز و پس از تنظیم کران/فعال‌سازی صریح اجرا می‌شود، آن هم بدون هرگونه تغییر در دیتابیس مدیریت.

## مرز Preview

- دیتابیس مدیریتی موجود `haniel-gold-tryon-test` دیگر نباید به Worker مشتری وصل شود؛ این DB برای بررسی‌های مدیریت محفوظ است.
- برای مشتری **یک D1 جدا** با نام `haniel-tryon-public-test` لازم است. فقط فایل `tryon-miniapp/db/0001_public_catalog.sql` را روی همان DB جدید اجرا کنید.
- Worker خصوصی مدیریت `haniel-gold-manager` و ربات `@Hani_El_manager_bot` به هیچ عنوان تغییر نکنند.
- **هم‌اکنون BotFather ربات آزمایشی `@Haniel_TryOn_bot` را از URL Preview داشبورد مدیریت جدا کنید.** دکمه Menu آن را Reset/Default کنید تا بعداً به Worker مشتری وصل شود. دیگر لینک Preview مدیریت را به مشتری ندهید.
- برای Worker جدید، GitHub root directory باید `tryon-miniapp` باشد، نه `telegram-miniapp`.
- هیچ Secret مربوط به حسابداری، `BOT_TOKEN` مدیر، `OWNER_TELEGRAM_ID` یا DB خصوصی نباید در Worker مشتری تعریف شود.

## وضعیت فعلی و کارهای باقی‌مانده

- ساختار سرویس مستقل و API محدود، موتور پردازش محلی و تست‌های اولیه در این شاخه نوشته شده‌اند.
- `tryon-sync` فقط یک موتور *در حالت غیرفعال* است؛ هنوز زمان‌بندی، ورود امن مالک برای تأیید و تکمیل تصویر محصول انجام نشده.
- کد مدیریت کالا (اصلی) و Production هیچ تغییری نکرده‌اند.
- تست‌های جدید باید روی GitHub Actions و Preview جدید موفق شوند. Build قبلی مدیریت برای این Worker معتبر نیست.
- هیچ داده واقعی مشتری، بکاپ حسابداری، توکن، تصویر خصوصی یا کالای ساختگی در مخزن منتشر نشده است.
- انتشار عمومی منوط به تأیید امنیت، تطابق عکس/محصول، آزمون واقعی موبایل تلگرام، تست عملکرد روی چند گوشی و انتخاب SKUهای مجاز است.
