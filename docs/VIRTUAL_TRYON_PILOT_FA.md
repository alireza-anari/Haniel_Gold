# HANI-EL GOLD — Virtual Try-On pilot (مرحله A)

این شاخه یک نمونه آزمایشی **محلی و بدون پرداخت** است؛ هنوز نسخه عمومی تلگرام، اتصال کاتالوگ و نتیجه فتورئالیستی تضمین‌شده نیست.

## مسیر تست

در سایت Cloudflare Pages با build فعلی (کپی کل `frontend/`): `/tryon/`.
در توسعه محلی پس از داشتن کل `frontend/`:

```sh
python3 -m http.server 8000 -d frontend
# http://localhost:8000/tryon/
```

در نسخه مقدماتی دو فایل لازم است: (۱) عکس مشتری با رضایت، (۲) تصویر واقعی همان قطعه طلا در PNG یا WebP با alpha شفاف. از عکس ساختگی یا محصول بازطراحی‌شده به عنوان مرجع SKU استفاده نشود. تصویر طلا باید از زاویه مناسب عکس مشتری تهیه شود.

* آپلود عکس با اندازه قابل قبول، اصلاح موقعیت با کشیدن محصول، اندازه/چرخش/سایه و ذخیره خروجی.
* تشخیص خودکار گوشواره و گردنبند **آزمایشی** است و برای بارگذاری مدل MediaPipe به CDN و Google Storage دسترسی نیاز دارد؛ در صورت عدم دسترسی، جای‌گذاری دستی فعال می‌ماند.
* رندر فعلاً یک **overlay دقیق پیکسلی با سایه ساده** است، نه شبیه‌ساز سه‌بعدی یا موتور فتورئالیستی. Segmentation/occlusion و profile محصول اختصاصی در مرحله بعد تکمیل می‌شود.
* داده‌های عکس مشتری در API آپلود نمی‌شوند؛ هیچ endpoint ذخیره عکس در این مرحله ساخته نشده است.
* شناسه `startapp` در MVP فقط نشان داده می‌شود و **ورود، مالکیت، صحت SKU یا قیمت** از آن استنباط نمی‌شود.
* هیچ مسیر انتشار/پرداخت جدید فعال نشده؛ `main`، `frontend/app.js` و `functions/` دست‌نخورده‌اند.

## کیفیت و محدودیت فعلی

- **PASS (محلی):** تست واحد تابع هندسه، `node --check`، گیت بارگذاری فایل، کنترل نسبت تصویر و مقیاس و تنظیم در محدوده.
- **UNVERIFIED:** اجرای واقعی MediaPipe روی گوشی، سازگاری Mini App تلگرام، خروجی با محصولات واقعی، طبیعی‌بودن، دقت گوش و گردن، رویت و نسخه‌سازی منابع CDN، و تست شبکه داخل ایران.
- **DO NOT RELEASE:** تا زمانی که ۲ محصول واقعی آماده، حداقل ۲۰ عکس تست بررسی، mask پوشاندگی تولید و کنترل کیفیت بصری تأیید شود.

## تست‌ها

```sh
node --check frontend/tryon/app.mjs
node --check frontend/tryon/geometry.mjs
node --test tests/tryon_math.test.mjs
```

## برنامه بعدی

۱. ثبت دو SKU واقعی در همین کاتالوگ، بدون ورود خودکار از تلگرام.
۲. تهیه cutout و mask واقعی هر SKU، با ابعاد/زاویه مجاز. اسکن و تأیید کارشناسی لازم است.
۳. افزودن API فقط‌خواندنی SKU تأییدشده و تست Telegram WebApp initData server-side برای عملیات حساس.
۴. افزودن پوشاندگی (مو، لباس، زنجیر دور گردن، دست) و گیت کیفیت؛ فعال‌کردن دکمه کانال فقط پس از آزمون.
۵. بررسی self-host کردن مدل MediaPipe و WASM در صورت مشکل دسترسی از ایران؛ اکنون برای سرعت نمونه‌سازی از CDN نسخه‌ثابت استفاده می‌شود.

## نکات امنیتی

از نسخه آزمایشی روی عکس اشخاص بدون رضایت استفاده نشود. عکس‌ها در JS و Canvas مرورگر پردازش می‌شوند؛ کاربر می‌تواند خروجی را ذخیره کند. آدرس `startapp` اعتبار امنیتی نیست؛ توکن ربات هرگز در فرانت قرار نگیرد.
 
## مرحله B — کنترل دارایی واقعی محصول

- فرم آزمایشی فقط PNG/WebP با alpha واقعی را برای کالا می‌پذیرد؛ تصویری که مستطیل مات، زمینه سفید یا پس‌زمینه تقریباً کامل دارد، رد می‌شود.
- با اسکن پیکسل‌های آلفا، محدوده واقعی زیورآلات شناسایی و پس‌زمینه اضافی حذف می‌شود. دارایی‌هایی با هاله نیمه‌شفاف، زنجیر فوق‌العاده باریک یا برخورد با لبه تصویر، پیام هشدار می‌گیرند.
- **قبولی ماشینی به معنی حفظ جزئیات تجاری کالا نیست.** باید حلقه‌ها، تعداد سنگ‌ها، ضخامت زنجیر، آویز و جای اتصال دستی با عکس اصلی مقایسه شوند.
- در عکس‌های ارسالی مشتری برای QA، فرد از قبل گردنبند داشته است. نسخه فعلی آن را حذف نمی‌کند و خروجی با دو گردنبند نمونه مناسبی برای انتشار نیست؛ عکس بدون گردنبند باید گرفته شود، یا حذف کنترل‌شده با رضایت و ابزار جداگانه بعداً توسعه یابد.
- عکس مرجع شخصی مشتری هرگز در این مخزن **عمومی** ذخیره نمی‌شود. هیچ تصویر تولیدشده با مدل مولد AI مبنای تأیید وفاداری محصول نیست.
- برش اولیه گردنبند A از استند آزمایش شد، اما حاشیه‌ها و زنجیر هنوز کیفیت کافی برای انتشار ندارند؛ محصول B و گوشواره از عکس با زمینه پیچیده نیازمند برش دستی و تأیید هستند.
- تست CI: `node --test tests/tryon_asset_quality.test.mjs tests/tryon_math.test.mjs`.

 
## مرحله C — اتصال ایمن کاتالوگ و لینک تلگرام (کد موجود؛ انتشار غیرفعال)

- مهاجرت مستقل `cloudflare/0007_tryon_assets.sql` یک جدول جدید و **خالی** برای دارایی‌های تأییدشده می‌سازد. داده محصولات، قیمت، موجودی و مشتری را تغییر نمی‌دهد. هنوز در حساب Cloudflare واقعی اجرا نشده است.
- `GET /api/v1/tryon/products/:slug` فقط محصول `published=1` با دارایی `approved=1` را نمایش می‌دهد. محصول منتشرنشده یا بدون تأیید: 404؛ نبود مهاجرت: 503 و بسته.
- `GET /api/v1/admin/tryon/assets` فهرست دارایی‌ها را فقط برای مدیر احرازهویت‌شده می‌دهد.
- `PUT /api/v1/admin/tryon/assets/:slug` با نشست مدیر، تطبیق `Origin` و `X-Haniel-CSRF`، بدنه محدود و `confirmReviewed: true`، دارایی را تأیید می‌کند.
- ورودی PUT: `{"assetUrl":"/api/v1/media/products/<uuid>.webp","productType":"necklace","approved":true,"confirmReviewed":true}`. تصویر باید قبلاً با API مدیریت بارگذاری شده و در MEDIA_KV واقعاً موجود باشد. برای لغو تأیید `approved:false` بفرستید.
- **پیش از هر تأیید** باید برش واقعی بدون هاله/بازسازی، شکل زنجیر و ابعاد نسبی با فایل اصلی مقایسه و ثبت شود. کنترل PNG/WebP و آلفا در مرورگر انجام می‌شود؛ آزمون سرور جایگزین بازبینی تخصصی نیست.
- با لینک `startapp=sku_<slug>`، مینی‌اپ ابتدا SKU را از API عمومی **صرفاً خواندنی** می‌گیرد و فایل شفاف همان SKU را از رسانه هم‌دامنه بارگذاری می‌کند. در این حالت آپلود دستی محصول غیرفعال می‌شود. لینک ساختگی فقط به 404 یا خطای امن منجر می‌شود.
- شناسایی کاربر Telegram برای خواندن کالای عمومی لازم نیست؛ در مراحل دارای اطلاعات خصوصی یا اقدام حساس، `initData` باید در سرور اعتبارسنجی شود. `initDataUnsafe` صرفاً در مسیر نمایش `start_param` استفاده شده است.
- انتشار پست از طریق ربات و تنظیم واقعی BotFather هنوز انجام نشده؛ هیچ ربات یا Webhook قدیمی فعال نشده است.
- **مسیر انتشار:** بررسی حساب واقعی Cloudflare → بررسی مهاجرت‌های فعلی D1 → اجرای 0007 فقط روی همان D1 صحیح → بارگذاری محصول شفاف تأییدشده → تأیید مدیر → تست محدود موبایل → سپس تنظیم لینک زیر پست‌های کانال.
- **مسیر بازگشت:** حذف تأیید هر SKU با PUT و `approved:false`، یا عدم انتشار لینک؛ حذف جدول بدون بکاپ پیشنهاد نمی‌شود.
- تست‌های Node محلی: `node --test tests/tryon_math.test.mjs tests/tryon_asset_quality.test.mjs tests/tryon_catalog.test.mjs`.

### نتایج آزمون مرورگری محدود
در Chromium با کد صفحه و ماژول‌های اصلی در سند تست محلی (بدون دسترسی شبکه): آپلود تصویر، تشخیص پس‌زمینه مات، نمایش کیفیت، آماده‌شدن Canvas و حفظ تصویر معتبر پس از بارگذاری نامعتبر بررسی شد. جای اولیه گردنبند در نسخه قبلی روی صورت قرار می‌گرفت و اصلاح شد. این روش **تست کامل HTTP/Cloudflare/Telegram نیست**. اجرای مستقیم localhost در محیط آزمایش با `ERR_BLOCKED_BY_ADMINISTRATOR` متوقف شد. بارگذاری MediaPipe از اینترنت، آزمون گوشی واقعی، تأیید fidelity و سنجش عملکرد همچنان نامشخص‌اند.
