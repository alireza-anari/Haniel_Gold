# بررسی آماده‌سازی GitHub

- ZIP اصلی شامل ۹۲ فایل، بدون فایل env واقعی یا دیتابیس و کش بود. فرانت‌اند، بک‌اند، تصاویر و لوگوها حفظ شدند.
- چهار وزن فونت تجاری تعبیه‌شده حذف و با مسیر فایل‌های دارای مجوز روی سرور جایگزین شدند. اسکنر اکنون فونت تعبیه‌شده، فایل فونت، لاگ، بکاپ و media را هم رد می‌کند.
- healthcheck داخلی Compose با هدر HTTPS برای پراکسی مورد اعتماد اصلاح شد؛ HTTP عمومی همچنان به HTTPS هدایت می‌شود.
- API و فرانت‌اند هم‌مبدأ از Caddy هستند؛ CORS عمومی فعال نشده. CSRF، کوکی امن، Allowed Hosts و مسیرهای static/media در تنظیمات موجودند.
- دیپلوی فقط workflow_dispatch است و در این مأموریت اجرا نمی‌شود؛ timeout اضافه و اجرای اسکریپت بکاپ با bash صریح شد.
- ۴۶ تست با Python 3.12 و SQLite ایزوله پاس شدند؛ makemigrations --check و JavaScript syntax و preflight پاس شدند. آزمون CI از Python 3.13 و PostgreSQL 16 استفاده می‌کند؛ نتیجه CI باید جداگانه بررسی شود.
- Docker/PostgreSQL/Caddy روی محیط محلی موجود نیست؛ build و تست عملیاتی Compose انجام نشده است. این بررسی جایگزین ممیزی امنیتی کامل نیست.
- قبل از Staging: دامنه و DNS، سرور، secret تصادفی، رمز PostgreSQL، hosts/origins، بکاپ و مانیتورینگ تنظیم شوند. سپس کلید Servix روی سرور، پروفایل rates و تأیید انسانی اولین نرخ و سیاست مالی؛ تا تکمیل SMS و درگاه و تست تراکنش، فروش عملیاتی آماده نیست.

- در اجرای تست با DEBUG=0 پنج درخواست کلاینت تست به‌جای HTTPS از HTTP استفاده می‌کردند و 301 می‌گرفتند؛ درخواست‌های تست به HTTPS اصلاح شدند و اجبار HTTPS پروداکشن حفظ شد. check --deploy فقط دو هشدار مربوط به HSTS subdomains/preload دارد؛ فعال‌سازی آن‌ها نیازمند بررسی دامنه واقعی است.

## تغییر بعدی به درخواست مالک
چهار وزن اصلی فونت یکان‌بخ از ZIP اولیه دوباره در CSS عمومی تعبیه شدند؛ توضیحات حذف فونت در گزارش اولیه، وضعیت تاریخی پیش از این درخواست است. راهنمای FONTS_FA.md وضعیت فعلی را توضیح می‌دهد.
