# HANI-EL GOLD — مدل فروش درخواستی / تأمین از بنکداری

## اصل تجاری
**ویترین عمومی همیشه قابل مشاهده است.** پذیرش درخواست به وقت `Asia/Tehran`، **شنبه تا چهارشنبه ۱۰ تا ۱۷؛ پنجشنبه ۱۰ تا ۱۴؛ جمعه و تعطیلات رسمی تعطیل** است. جزئیات تأمین داخلی فقط در پنل مدیریت باقی می‌ماند؛ متن مشتری صرفاً درباره بررسی قیمت و امکان ثبت نهایی توضیح می‌دهد. هیچ کالایی صرفاً به‌دلیل درج در کانال یا سایت، موجود یا رزرو‌شده معرفی نمی‌شود.

مراحل:
1. مشتری انتخاب‌ها را در سبد «درخواست بررسی» قرار می‌دهد؛ قیمت نمایشی فقط در صورت نرخ معتبر Servix و اطلاعات کامل محصول نمایش داده می‌شود.
2. مشتری نام و موبایل را می‌دهد و Turnstile را تکمیل می‌کند. سرویس در ساعات غیرمجاز یا بدون گزینه `REQUESTS_ENABLED=1`، درخواست را نمی‌پذیرد.
3. D1 یک `purchase_inquiries` با snapshot وزن، عیار، اجرت، سود و قیمت **غیرقطعی** ذخیره می‌کند. هیچ کارت بانکی، آدرس یا وجهی جمع‌آوری نمی‌شود.
4. مدیر در `/admin` موجودی بنکداری و قیمت واقعی را استعلام می‌کند و وضعیت را تغییر می‌دهد.
5. قبل از هر دریافت وجه، تأیید عملی قابل‌اتکا و بهتر است رزرو/تهیه قطعی کالا، بازبینی حقوقی و سازوکار رسمی پرداخت و استرداد لازم است. فرآیند دریافت وجه، فاکتور، خرید، بسته‌بندی و ارسال **هنوز پیاده‌سازی نشده**.
6. اگر کالا ناموجود شود یا قیمت تغییر کند، درخواست رد یا پیشنهاد جدید با رضایت مجدد مشتری ارسال می‌شود. هیچ‌وقت مبلغ قدیمی تعهد قطعی محسوب نمی‌شود.

## راه‌اندازی محافظت‌شده (هنوز فعال نکن)
1. ابتدا SQL فایل `cloudflare/0003_inquiry_telegram.sql` را در **D1 موجود سایت** اجرا کن؛ داده‌های قبلی پاک نمی‌شوند.
2. در Pages → Settings → Variables and Secrets (Production) این متغیرها برای **درخواست بررسی** لازم‌اند:
   - `REQUESTS_ENABLED` = `1` فقط بعد از تکمیل الزامات و آزمون‌ها، تا آن زمان **تعریف نکن**.
   - `TURNSTILE_SITE_KEY` = Site Key عمومی یک Widget ثبت‌شده برای دامنه مقصد (Text variable).
   - `TURNSTILE_SECRET` = Secret Key واقعی Turnstile (Secret).
   - `INQUIRY_RATE_SALT` = یک رشته امن تصادفی با حداقل ۲۴ کاراکتر (Secret).
   - `INQUIRY_OPEN_DAYS` = `sat,sun,mon,tue,wed,thu`. جمعه بسته است. ساعت‌ها از کد بررسی می‌شوند.
   - `INQUIRY_CALENDAR_VERIFIED_UNTIL` = تاریخ میلادی `YYYY-MM-DD` تا آخر دوره‌ای که تعطیلات رسمی و غیرمترقبه **واقعاً بازبینی شده‌اند**. در نبود آن یا پس از پایان دوره، پذیرش درخواست غیرفعال است.
   - `INQUIRY_CLOSED_DATES` = فهرست تاریخ‌های میلادی تعطیل به‌صورت `YYYY-MM-DD,YYYY-MM-DD` برای دوره بازبینی. مطابق تقویم رسمی و تعطیلی‌های موردی تنظیم شود.
   - `INQUIRY_EMERGENCY_CLOSED` = `1` برای تعطیلی فوری پذیرش درخواست؛ با حذف یا `0` رفع می‌شود. اطلاعات سبد پاک نخواهد شد.
   - تنظیمات فوق صرفاً برای ساعات درخواست مشتری است، نه انتشار برنامه داخلی تأمین برند.
3. با وجود هر چهار مقدار، فرانت‌اند در حالت `?catalog=live` به‌جای سبد خرید کلاسیک، سبد درخواست بررسی را نمایش می‌دهد. تغییر تنظیمات نیازمند Redeploy است.
4. **قبل از فعال‌سازی**: پروانه‌ها/الزامات مرتبط با معاملات آنلاین مصنوعات، حفاظت داده مشتری، سازوکار تماس رسمی، تأمین بنکداری و مرجوعی بررسی شوند.
5. `STAGING_API_ACTIVE` را صرفاً برای فعال‌کردن یک قابلیت روشن نکن؛ این تنظیم کاتالوگ عمومی را هم تغییر می‌دهد. نسخه فعلی preview با `?catalog=live` قابل آزمایش است.

### امنیت
- سیاست ثبت درخواست **fail-closed** است؛ به Turnstile، IP واقعی و salt نیاز دارد؛ حداکثر سه ارسال در ساعت به ازای هش IP. اطلاعات مشتری به‌صورت خام در مخزن Git یا لاگ چاپ نمی‌شوند.
- شماره مشتری فقط برای مدیر احرازهویت‌شده در فهرست درخواست‌ها قابل دیدن است. نیاز به سیاست نگهداری و حذف داده، مدیریت پشتیبانی و دسترسی مدیر قبل از راه‌اندازی نهایی وجود دارد.
- API وضعیت سفارش برای مشتری، پیامک و فاکتور هنوز وجود ندارند؛ لینک پرداخت دستی/کارت به کارت را بدون مشورت حقوقی فعال نکن.
- وقتی وضعیت API عمومی از `ready` خارج شود، قیمت معتبر نیز غیرفعال می‌شود؛ ثبت درخواست بدون نرخ فعلی فقط در حالت قیمت نامشخص و بدون تعهد مالی مجاز است.

## Telegram → پیش‌نویس سایت
ربات باید توسط مالک در BotFather ایجاد شود و به‌عنوان مدیر کانال مجاز انتخابی اضافه شود. Webhook رسمی فقط رویدادهای `channel_post` و `edited_channel_post` را دریافت می‌کند.

برای پست‌هایی که در سایت هم وارد شوند، متن استاندارد:

```text
#HANIEL_SITE
نام: [نام واقعی محصول]
شناسه: [کد انگلیسی یکتا]
دسته: [دسته موجود سایت]
وزن: [وزن واقعی پس از تأیید]
عیار: [عیار واقعی پس از تأیید]
توضیح: [توضیحات قابل اثبات]
```

**مقادیر داخل کروشه راهنما هستند و داده واقعی محسوب نمی‌شوند.** **اجرت و سود داخلی را در کپشن عمومی تلگرام ننویس**؛ اینها اطلاعات تجاری برند هستند و بهتر است در فرم مدیریت تکمیل شوند. پارسر در صورت وجود فیلد اجرت و سود آنها را به پیش‌نویس منتقل می‌کند، ولی انتشارشان در کانال توصیه نمی‌شود. هر فیلد نامعلوم باید خالی یا بعداً تکمیل شود؛ اطلاعات حدسی وارد نکن. تصاویر واقعی به همان پست الصاق شوند.

- Webhook endpoint: `POST https://haniel-gold.pages.dev/api/v1/integrations/telegram`
- Only when `TELEGRAM_IMPORT_ENABLED=1`, `TELEGRAM_WEBHOOK_SECRET` (Secret), and either `TELEGRAM_CHANNEL_USERNAME=haniellgold` or `TELEGRAM_CHANNEL_ID` are configured. If both username and numeric ID exist, both must match the Telegram webhook event.
- در متد `setWebhook` تلگرام باید همان `TELEGRAM_WEBHOOK_SECRET` را به‌صورت پارامتر `secret_token` و `allowed_updates=["channel_post","edited_channel_post"]` قرار دهی. این کلید را در متن گفتگو، لینک عمومی یا GitHub قرار نده.
- `update_id` و `message_id` از تکرار و ویرایش بی‌مورد پست جلوگیری می‌کنند؛ فقط کانال شناخته‌شده معتبر است.
- یک رکورد `telegram_product_drafts` در D1 ایجاد و به پنل بررسی منتقل می‌شود؛ پست بدون نشانگر نادیده گرفته می‌شود.
- **گرفتن فایل عکس از Telegram Bot API و انتقال امن به `MEDIA_KV` هنوز پیاده‌سازی نشده است**؛ فقط `photo_file_id` برای بررسی ذخیره می‌شود. در پنل مدیر می‌توان اطلاعات متن را به فرم محصول انتقال داد و عکس واقعی را دستی آپلود کرد. انتشار از روی ربات هنوز انجام نمی‌شود.
- پیام‌های چندعکسی آلبوم (`media_group_id`) نیازمند تجمیع مستقل و مدیریت حذف/ویرایش هستند. قبل از اتوماسیون کامل گالری پیاده شوند.
- این مسیر به حساب Telegram واقعی و دریافت Bot Token/Channel ID و تنظیم Webhook نیاز دارد، که در این گفتگو دسترسی به آن‌ها نداریم.

## ریسک‌های خارج از کد
- قبل از گرفتن وجه برای محصولی که هنوز در مالکیت/رزرو تأمین‌کننده نیست، الزامات قانونی و امکان مجازبودن شیوه فروش باید به‌طور مستقل بررسی شود.
- برند می‌تواند تأمین‌کنندگان خود را به‌عنوان اطلاعات داخلی نگه دارد، اما ادعای موجودی قطعی، آماده‌ارسال بودن، تولید توسط برند یا زمان تحویل تضمین‌شده بدون پشتوانه نادرست است. در صورت پرسش مستقیم مشتری درباره تأمین، پاسخ صادقانه داده شود.
- دوره بازبینی تقویم باید با تقویم رسمی سال مربوط و تعطیلی‌های ناگهانی هماهنگ بماند؛ در تعطیلی پیش‌بینی‌نشده `INQUIRY_EMERGENCY_CLOSED=1` را فعال کن.
- سایت فعلی `pages.dev` ممکن است برای کاربران برخی اپراتورهای ایران بدون VPN دسترس‌پذیر نباشد؛ حتی با تکمیل سفارش‌ها، تست با سیم‌کارت‌های ایران و استقرار جایگزین ضروری است.
- شنبه تا چهارشنبه ۱۰–۱۷ و پنجشنبه ۱۰–۱۴ در کد تنظیم شده‌اند؛ جمعه و تاریخ‌های تعطیل مسدود هستند. تقویم تعطیلات باید به‌طور منظم بازبینی شود.
