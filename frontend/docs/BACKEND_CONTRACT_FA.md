# قرارداد پیشنهادی اتصال فرانت به بک‌اند HANI-EL GOLD

**وضعیت:** این سند نقشه پیاده‌سازی آینده است؛ وجود هیچ‌یک از سرویس‌های زیر را ادعا نمی‌کند.

## سرویس‌هایی که در کد فرانت مسیر اتصال ابتدایی دارند

پیش از اجرای `app.js` تنظیم زیر در صفحه درج شود:

```html
<script>window.HANIEL_CONFIG = { apiBaseUrl: 'https://YOUR-API-ORIGIN', apiTimeout: 10000 };</script>
```

### دریافت محصولات

`GET /v1/catalog/products?limit=100`

پاسخ پیشنهادی:

```json
{
  "items": [
    {
      "id": "valid-url-safe-id",
      "name": "نام معتبر محصول",
      "category": "گردنبند",
      "style": "مینیمال",
      "images": ["https://your-cdn.example/product.webp"],
      "alt": "توضیح عکس واقعی محصول",
      "weightGrams": null,
      "karat": null,
      "price": {"amountToman": null},
      "inventoryStatus": "unknown"
    }
  ]
}
```

نکات: شناسه فقط حروف انگلیسی/عدد/خط تیره و زیرخط باشد؛ تصاویر معتبر با HTTPS؛ قیمت فقط با واحد مشخص «تومان» و عدد تأییدشده؛ مقدار `null` به معنی نبود داده و **نباید با صفر جایگزین شود**. وضعیت موجودی فقط پس از صحت‌سنجی سرور `available` شود؛ سایر مقادیر به‌معنی عدم تأیید قابلیت سفارش هستند.

### درخواست کد ورود

`POST /v1/auth/otp/request`

```json
{"mobile": "09XXXXXXXXX"}
```

### بررسی کد ورود

`POST /v1/auth/otp/verify`

```json
{"mobile": "09XXXXXXXXX", "code": "******"}
```

فرانت پس از پاسخ موفق باید در مرحله اتصال حساب مشتری، اطلاعات واقعی حساب را از `/v1/account/me` بخواند؛ در V5 هیچ احراز هویت واقعی یا نشست معتبر ایجاد نمی‌شود. نشست ایمن ترجیحاً با کوکی `HttpOnly` و `Secure` مدیریت شود.

### ارتباط با پشتیبانی

`POST /v1/support/messages`

```json
{"name":"...", "mobile":"09XXXXXXXXX", "topic":"...", "message":"..."}
```

در دمو هیچ داده‌ای ارسال نمی‌شود. موفقیت فقط پس از دریافت پاسخ معتبر سرور اعلام شود.

## endpointهای لازم در مرحله بک‌اند (هنوز سیم‌کشی نشده‌اند)

- `GET /v1/catalog/products/:id` — مشخصات کامل، تصاویر واقعی، عیار، وزن، نوع و ابعاد قطعه.
- `GET /v1/account/me` — نشست کاربر؛ بدون افشای داده مشتری به مرورگر دیگر.
- `GET /v1/orders` و `GET /v1/orders/:id` — تاریخچه و وضعیت واقعی سفارش‌ها.
- `GET/POST/PATCH/DELETE /v1/account/addresses` — نشانی‌های حساب، بعد از احراز هویت.
- `POST /v1/cart/quote` — استعلام وزن/قیمت/اجرت/سود/مالیات/هزینه معتبر، موجودی و تاریخ انقضای استعلام، با شناسه quote.
- `POST /v1/orders` — سفارش‌گذاری فقط از `quoteId` معتبر، همراه با شناسه یکتای درخواست (idempotency key).
- `POST /v1/payments/start` و اعتبارسنجی callback/webhook سمت سرور — آغاز و تأیید پرداخت.
- endpointهای تنظیمات رسمی فروشگاه: مجوزها، راه‌های تماس، شرایط ارسال و مرجوعی، روش‌های ارسال و هزینه‌ها.

## اصول اجباری هنگام اتصال

1. قیمت طلا، اجرت، سود و مبلغ نهایی سمت سرور محاسبه و تأیید شوند؛ هیچ عدد نمایشی از کلاینت منبع حقیقت نباشد.
2. موجودی هنگام استعلام و سفارش دوباره کنترل شود؛ رزرو هم‌زمان کالا مدیریت شود.
3. نرخ و مدت اعتبار quote روشن باشد؛ تغییر قیمت باید پیش از پرداخت به کاربر نشان داده شود.
4. احراز هویت پیامکی محدودیت نرخ، انقضا، محافظت در برابر تکرار و CSRF داشته باشد.
5. قوانین مالیاتی/حقوقی و مجوزها فقط پس از تأیید متخصص مربوطه منتشر شوند.
6. انتقال فقط HTTPS، پرداخت فقط از سرویس مجاز و تأیید تراکنش سمت سرور.
7. عکس و متادیتای محصول از کاتالوگ معتبر بیایند و تصاویر مفهومی آزمایش حذف شوند.
8. صفحات محصول و مجموعه برای سئوی تولیدی بهتر است مسیرهای مستقیم و SSR/SSG داشته باشند، نه صرفاً hash.
