# HANI-EL GOLD — Django REST + PostgreSQL Backend (Foundation v1)

این پروژه **کد واقعی بک‌اند و معماری اولیهٔ قابل‌توسعه** برای فرانت‌اند تأییدشده HANI-EL GOLD است. مدل‌ها، Admin، مسیرهای API، قیمت‌گذاری مبتنی بر Decimal، سفارش با idempotency و رزرو موجودی، OTP قابل اتصال و مستندات موجود است. **این بسته به‌تنهایی فروشگاه آماده انتشار/پرداخت واقعی نیست.**

## انتخاب فنی

- Django 5.2 LTS، Django REST Framework 3.17، PostgreSQL 16 و psycopg 3
- Python 3.13، Django Admin و API نسخه‌گذاری شده `/v1/`
- اطلاعات مالی: تومان در DB، Decimal نه float، نرخ به ازای عیار مشخص و تاییدشده
- OTP و پرداخت در حالت پیش‌فرض عمداً غیرفعال تا قرارداد اپراتور/درگاه قطعی شود

## اجرای محلی

1. Python 3.13 و PostgreSQL 16/17 نصب شود.
2. `python -m venv .venv` و فعال‌سازی محیط مجازی.
3. `pip install -r requirements.txt` (اینترنت لازم است).
4. `cp .env.example .env`، سپس SECRET_KEY و مقادیر POSTGRES را جایگزین کنید. اطلاعات مثال رمز واقعی نیستند.
5. دیتابیس PostgreSQL و کاربر موردنیاز را ایجاد کنید (یا از سرویس `database` در compose استفاده کنید).
6. `python manage.py migrate`
7. `python manage.py createsuperuser`
8. `python manage.py runserver` و بازکردن `/admin/` و `/v1/health`.

روش Docker: `cp .env.example .env`، اصلاح گذرواژه و کلید، `docker compose up -d --build` و یک‌بار `docker compose exec web python manage.py migrate` و `docker compose exec web python manage.py createsuperuser`.

## ترتیب تکمیل داده‌ها در پنل

1. دسته‌بندی‌ها و محصولات واقعی و تصاویر HTTPS
2. وزن و عیار واقعی هر کالا، درصد اجرت و سود تأییدشده، موجودی
3. نرخ تأییدشده مخصوص همان عیار با زمان، مهلت اعتبار آینده و منبع ثبت؛ فقط یک نرخ فعال برای هر عیار
4. تنظیم `PricingPolicy` مطابق قواعد واقعی، مالیات و ارسال و سپس فعال‌سازی `approved`
5. فعال‌سازی سرویس پیامک واقعی و درگاه واقعی پس از تکمیل قراردادها و ارزیابی امنیت

هیچ کالایی به‌صورت خودکار Seed نمی‌شود. قیمت و موجودی «نمایشی» وجود ندارد. نرخ‌ها یا سیاست‌های مالیات بدون تأیید در quote استفاده نمی‌شوند.

## تست و محدودیت فعلی

- تست‌ها در `tests/test_commerce.py` قرار دارند: `HANIEL_TEST_SQLITE=1 DJANGO_DEBUG=1 python manage.py test tests` فقط برای smoke/unit؛ **تست سازگاری تراکنش و ریسِ موجودی باید جداگانه روی PostgreSQL انجام شود**.
- در محیط تولید این فایل، کتابخانه‌های Django/psycopg نصب نبودند و شبکه pip برای نصب در دسترس نبود؛ صرفاً بررسی نحوی/ساختاری انجام شده است. اجرای تست Django و اتصال PostgreSQL هنوز باید در محیط دارای وابستگی انجام شود.
- برای پیاده‌سازی SMS، درگاه پرداخت، ارسال، مالیات و فاکتور واقعی به قرارداد ارائه‌دهندگان و تصمیم‌های عملیاتی فروشگاه نیاز است.

سند مسیرها: `docs/API_FA.md` — سند ملاحظات مالی/امنیتی: `docs/SECURITY_AND_PRICING_FA.md`.

## افزونه V2 — نرخ خودکار و قیمت محاسبه‌شده

به فایل [docs/AUTOMATIC_GOLD_RATES_FA.md](docs/AUTOMATIC_GOLD_RATES_FA.md) مراجعه کنید. دریافت نرخ ۱۸ عیار از وب‌سرویس مجاز هر ۳۰ دقیقه زمان‌بندی شده است، اما تا دریافت اشتراک واقعی و API token کار نمی‌کند. اولین نرخ و تغییرات مشکوک نیازمند تأیید مدیر ارشد هستند. قیمت محصول به‌صورت خودکار و **بدون فیلد قیمت دستی** محاسبه می‌شود. هزینه اجرت ثابت اختیاری، درصد اجرت و سود در پنل محصول قابل ثبت هستند. قیمت و مالیات نهایی با تنظیمات معتبر سرور محاسبه می‌شوند.

## افزونه V3 — اتصال رسمی به Servix

از این نسخه، دریافت‌کنندهٔ رسمی Servix پیاده‌سازی شده است و به‌طور پیش‌فرض از نماد `GOLD_18_RLS` در آدرس HTTPS ثابت و هدر `X-API-Key` استفاده می‌کند. استفاده از کلید فقط روی سرور انجام می‌شود؛ قیمت و زمان داده قبل از ورود به PostgreSQL اعتبارسنجی می‌شوند. استعلام هر نیم ساعت، ممیزی و گارد توقف بعد از خطای 429 اضافه شده است. برای راه‌اندازی گام‌به‌گام [راهنمای Servix](docs/SERVIX_SETUP_FA.md) را ببینید. تا زمانی که توکن واقعی، سیاست مالی تاییدشده و سرور راه‌اندازی نشده، قیمت عملیاتی فعال نیست.
