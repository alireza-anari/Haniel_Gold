# HANI-EL GOLD — نرخ خودکار و محاسبه قیمت | Backend V2

## قرارداد مالی و منبع نرخ

**منبع پیشنهادی:** وب‌سرویس مجاز و قراردادی TGJU (یا ارائه‌دهنده معتبر جایگزین با مستندات و مجوز لازم). برنامه هیچ URL اختصاصی، توکن و ساختار JSON ادعایی برای TGJU جعل نمی‌کند. پس از خرید سرویس، تنظیمات داخل `.env` وارد می‌شوند.

**واحد مبنای سیستم:** تومان به ازای هر گرم طلای ۱۸ عیار. در خروجی رسمی سرویس، واحد پول را مستقل بررسی کنید؛ در `.env` یکی از `RIAL` یا `TOMAN` را به‌صورت قطعی مشخص کنید. تبدیل ریال به تومان دقیقاً تقسیم بر ۱۰ است. ورودی نرخ با `Decimal` پردازش می‌شود.

**فرمول پیشنهادی (نیازمند تأیید حسابداری و ضوابط فروش):**

```text
raw_gold = weight_grams × rate_toman_per_gram_at_product_karat
workmanship = raw_gold × workmanship_percent / 100 + workmanship_fixed_toman
profit = (raw_gold + workmanship) × profit_percent / 100
VAT = (workmanship + profit) × approved_tax_percent / 100  (اگر tax_basis=fee_profit)
item_total = raw_gold + workmanship + profit + VAT
order_total = Σ(item_total × quantity) + approved_shipping_toman
```

هر بخش به تومان صحیح با ROUND_HALF_UP گرد می‌شود. **درصد مالیات و مبنای آن پیش‌فرض ندارند** و باید پس از بررسی حقوقی/حسابداری در `PricingPolicy` تأیید شوند. قیمت نمایشی محصول هزینه حمل را شامل نمی‌شود؛ مبلغ حمل در استعلام سبد محاسبه می‌شود. از فرمول نهایی بدون تأیید استفاده تجاری نکنید.

## فیلدهای مدیر محصول

- نام، شناسه، دسته، سبک، توضیحات و تصاویر واقعی
- `weight_grams` — وزن با دقت ۴ رقم اعشار
- `karat` — عیار؛ **فعلاً اتوماتیک فقط نرخ ۱۸ عیار**. برای عیارهای دیگر منبع نرخ مستقل و معتبر نیاز است
- `workmanship_percent` — اجرت درصدی (در روش صرفاً ثابت می‌تواند خالی باشد)
- `workmanship_fixed_toman` — اجرت ثابت، در صورت وجود، به قیمت اجرت درصدی افزوده می‌شود
- `profit_percent` — درصد سود روی وزن طلای خام به‌علاوه اجرت
- موجودی در `Inventory`
- `PricingPolicy` برای مالیات و هزینه ارسال؛ نه در فرم محصول

**هیچ قیمت ثابت در مدل یا فرم محصول وجود ندارد.** مقدار `price.amountToman` در API از نرخ فعال و تأییدشده محاسبه می‌شود و در حالت ناامن/بدون اطلاعات `null` خواهد بود.

## اجرای هر نیم ساعت

- `rate-worker` در `compose.yaml` در ساعات `:00` و `:30` به وقت `Asia/Tehran` فراخوانی می‌کند.
- `python manage.py sync_gold_rate` — دریافت دستی برای بررسی اتصال
- `python manage.py run_rate_scheduler` — اجرای زمان‌بند مداوم
- اگر با cron استفاده شد، **هم‌زمان rate-worker را خاموش کنید**:
  `0,30 * * * * cd /path && .../python manage.py sync_gold_rate`
- در PostgreSQL، ردیف منفرد RateSyncState در تراکنش قفل می‌شود تا نسخه قیمت در وسط صدور استعلام تغییر نکند.
- هر دریافت در `RateSyncAttempt` گزارش می‌شود و نرخ‌های تاریخی GoldRate برای سفارش‌های قبلی حفظ می‌شوند.

## کنترل‌های حفاظتی

1. فقط HTTPS و نام دامنه دقیق `GOLD_FEED_ALLOWED_HOST`؛ ریدایرکت مجاز نیست.
2. کلید API فقط سمت سرور؛ هیچ‌وقت در JS عمومی یا Git قرار نگیرد.
3. زمان ثبت نرخ باید دقیقاً ISO-8601 با timezone باشد؛ داده قدیمی یا زمان آینده رد می‌شود.
4. دامنه مجاز تغییر نرخ نسبت به نوبت قبل (`GOLD_FEED_MAX_CHANGE_PERCENT`) **قابل تنظیم** است. مقدار نمونه ۵٪ صرفاً آستانه احتیاطی داخلی است و باید بر اساس منبع و نوسان واقعی بازبینی شود.
5. اولین نرخ به تأیید انسانی مدیر ارشد نیاز دارد؛ نرخ مشکوک در پنل `Rate Sync Attempts` قابل بازبینی است و صرفاً مدیر ارشد می‌تواند یک مورد تازه و بررسی‌شده را تأیید کند.
6. داده تکراری با زمان و نرخ مساوی تأیید مجدد نمی‌شود و زمان اعتبارش مصنوعاً افزایش نمی‌یابد.
7. اگر پاسخ خراب یا قطع شد، نرخ جدید منتشر نمی‌شود؛ تا زمان اعتبار آخرین نرخ و بدون بلوکه شدن، نمایش و استعلام مجاز است. پس از انقضا، قیمت و ثبت سفارش متوقف می‌شود. تغییر مشکوک فوراً باعث توقف استعلام می‌شود.
8. صدور Quote و ثبت Order همچنان نرخ معتبر و موجودی کافی را در سرور و در تراکنش بررسی می‌کنند.

## اتصال وب‌سرویس پس از تهیه اشتراک

در `.env`:

```dotenv
GOLD_FEED_URL=                  # URL واقعی مستندات ارائه‌دهنده
GOLD_FEED_ALLOWED_HOST=         # دامنه دقیق URL بالا
GOLD_FEED_API_KEY=              # توکن معتبر در سمت سرور
GOLD_FEED_AUTH_HEADER=Authorization
GOLD_FEED_AUTH_PREFIX="Bearer " # دقیقاً مطابق قرارداد واقعی سرویس
GOLD_FEED_VALUE_PATH=           # مسیر JSON قیمت گرم ۱۸ عیار؛ مثلاً market.gold18.value در یک سرویس فرضی
GOLD_FEED_TIMESTAMP_PATH=       # مسیر JSON زمان مشاهده؛ مثلاً market.gold18.updated_at در یک سرویس فرضی
GOLD_FEED_UNIT=                 # RIAL یا TOMAN، طبق قرارداد واقعی
GOLD_FEED_PROVIDER_NAME=tgju_licensed
```

دو نمونه مسیر `market.gold18.*` صرفاً **نمونه ساختگی شکل JSON** هستند و به‌عنوان ساختار واقعی TGJU معرفی نشده‌اند.

اگر API زمان معتبر ارائه ندهد، باید بعد از بررسی مستندات یک adapter مخصوص نوشته شود؛ به‌جای حدس‌زدن ساعت ثبت قیمت، سیستم ایمن متوقف می‌شود. همچنین در این نسخه تبدیل خودکار نرخ ۱۸ به ۲۴ عیار انجام **نمی‌شود**.

## API و فرانت

`GET /v1/market/gold` اطلاعات منبع، `observedAt`، `validUntil`، `status`، `pricingStatus` و `tomanPerGram` را ارائه می‌دهد.

`GET /v1/catalog/products` و `/v1/catalog/products/{slug}` در `price`، مقدار `amountToman`, `currency`, `status`, `breakdown` و زمان اعتبار نرخ را برمی‌گردانند. برای چند محصول، نرخ و policy فقط یک‌بار در هر درخواست خوانده می‌شود.

`POST /v1/cart/quote` هر بار قیمت معتبر و موجودی را در سرور محاسبه و استعلام زمان‌دار صادر می‌کند. UI باید `validUntil` را نمایش دهد و پس از تغییر نرخ، مجدداً کاتالوگ و استعلام را دریافت کند؛ داده قدیمی از کلاینت قابل اعتماد نیست.

**فرانت V5 هنوز به این API متصل نشده است.** نمایش واقعی قیمت در سایت پس از اتصال و اصلاح renderer فرانت انجام می‌شود؛ تا آن زمان داده‌ها نمایشی‌اند.

## تست و عملیاتی‌سازی

کد parser مستقل از Django با `python -m unittest tests.test_rate_feed` آزمایش می‌شود. پس از نصب Django، تست‌ها را با `HANIEL_TEST_SQLITE=1 python manage.py test tests` و در PostgreSQL نیز اجرا کنید.

ترتیب راه‌اندازی: ۱) فایل `.env`، ۲) راه‌اندازی PostgreSQL، ۳) `python manage.py migrate`، ۴) ساخت مدیر با `createsuperuser`، ۵) ثبت و تأیید `PricingPolicy`، ۶) ثبت محصولات، تصاویر و موجودی، ۷) تنظیم کلید منبع رسمی، ۸) اجرای اولین دریافت و تأیید مدیر، ۹) فعال‌کردن زمان‌بند و مانیتورینگ. قبل از تولید، اتصال واقعی، کنترل خطا، بازگشت از نسخه قبل و تست هم‌زمانی PostgreSQL انجام شود.
