# راهنمای اتصال Servix به بک‌اند HANI-EL GOLD — نسخه V3

> **مهم:** این پروژه آمادهٔ دریافت نرخ است، ولی تا زمانی که کلید واقعی خودتان در فایل محرمانهٔ `.env` قرار نگیرد و سرویس روی سرور اجرا نشود، به حساب Servix شما متصل نشده است. **کلید API را در چت، گیت‌هاب، HTML فرانت‌اند یا فایل ZIP ارسال نکنید.**

## ۱. دریافت کلید Servix

1. وارد https://servix.cc شوید.
2. مسیر **Profile → API Keys** را باز کنید.
3. یک کلید فعال بسازید و فقط روی سیستم یا سرور امن خودتان نگهداری کنید.
4. پلن رایگان طبق راهنمای فعلی Servix روزانه ۵۰ درخواست دارد؛ زمان‌بندی هر نیم ساعت ۴۸ درخواست در هر ۲۴ ساعت مصرف می‌کند. تست‌های دستی، درخواست‌های جایگزین یا فراخوانی‌های اضافی ممکن است سهمیه را پر کنند.

**مستندات منبع:**
- https://servix.cc/docs/getting-started
- https://servix.cc/api/gold
- https://servix.cc/docs/current-prices
- https://servix.cc/docs/errors-and-rate-limits

## ۲. نصب و تنظیم سرویس

از ریشه پروژه (در پوشه‌ای که `manage.py` قرار دارد):

```bash
cp .env.example .env
```

در `.env` این متغیرها را تنظیم کن:

```dotenv
GOLD_FEED_PROVIDER_NAME=servix
SERVIX_API_KEY=YOUR_OWN_PRIVATE_SERVIX_API_KEY
```

سپس `DJANGO_SECRET_KEY` و `POSTGRES_PASSWORD` و مقادیر زیرساخت واقعی‌ات را هم با مقادیر امن تنظیم کن؛ `DJANGO_DEBUG=0` فقط روی هاست با HTTPS و تنظیمات کامل امنیتی مناسب است.

نکته: آدرس رسمی Servix، نماد و واحد داخل کد ثابت و اعتبارسنجی شده‌اند؛ چیزی را از فرانت‌اند ارسال نمی‌کنیم.

## ۳. اجرای محلی با Docker / PostgreSQL

```bash
docker compose up -d --build
docker compose exec web python manage.py migrate
docker compose exec web python manage.py createsuperuser
```

در Docker، سرویس `rate-worker` جدا از وب‌سرور فعالیت می‌کند و در نیم‌ساعت‌های تهران نرخ را دریافت می‌کند. همزمان فقط یک نسخه از این Worker اجرا کن. اتصال سمت وب‌سرور با PostgreSQL انجام می‌شود.

روش بدون Docker: پس از نصب وابستگی‌های Python و راه‌اندازی PostgreSQL، دستورهای `python manage.py migrate`، `python manage.py createsuperuser` و سپس اجرای جداگانهٔ `python manage.py run_rate_scheduler` را استفاده کن.

## ۴. یک تست واقعی با صرف یک درخواست

```bash
docker compose exec web python manage.py check_servix
```

این دستور **فقط یک درخواست Servix** انجام می‌دهد، داده و زمان ثبت را اعتبارسنجی می‌کند و سپس نرخ را نشان می‌دهد؛ ولی **هیچ قیمتی در DB فعال نمی‌کند**. اگر `INVALID_RATE` دیدی، ممکن است زمان داده قدیمی، واحد اشتباه یا پاسخ نامعتبر باشد؛ خطا را بدون ارسال کلید API بررسی کن.

بعد از موفقیت:

```bash
docker compose exec web python manage.py sync_gold_rate
```

**مهم:** نخستین نرخ عمداً با وضعیت `rejected` ثبت می‌شود تا مدیر ارشد آن را پس از بررسی مستقل تأیید کند؛ پیام خروج غیرصفر در همین مرتبهٔ اول غیرعادی نیست.

## ۵. فعال‌سازی نرخ اول در Django Admin

1. `http://localhost:8000/admin/` را در مرورگر محلی باز کن.
2. با حساب **Superuser** وارد شو.
3. در بخش **Rate sync attempts / تلاش‌های دریافت نرخ**، جدیدترین تلاش مردودِ مربوط به اولین نرخ Servix را انتخاب کن.
4. پس از بررسی مستقل قیمت، **پذیرش نرخ مردود** را اجرا کن.
5. در **Gold rates** نرخ تأییدشده، زمان داده و `valid_until` را بررسی کن.
6. در **PricingPolicy** قواعد تاییدشده اجرت، سود، مالیات و هزینه ارسال را تکمیل و تایید کن. **هیچ مقدار مالیاتی را صرفاً برای آزمایش به‌عنوان رقم واقعی فروش فعال نکن.**

پس از آن نرخ‌های عادی به‌صورت اتوماتیک پذیرفته خواهند شد؛ تغییر بیش از آستانه پیکربندی‌شده یا زمان غیرمعتبر دوباره به تأیید مدیر نیاز دارد.

## ۶. وضعیت نرخ در Django و فرانت‌اند

```
GET /v1/market/gold
```

کلید API Servix به مرورگر ارسال نمی‌شود. پاسخ عمومی وضعیت‌ها را نشان می‌دهد:

- `status=ready`: نرخ معتبر و تأییدشده وجود دارد.
- `status=expired`: مهلت نرخ به پایان رسیده است.
- `status=blocked`: نرخ اولیه یا تغییر مشکوک نیازمند تأیید است.
- `pricingStatus=policy_missing`: سیاست مالی هنوز تأیید نشده است.
- `pausedUntil`: در صورت اتمام سهمیه، زمان پایان توقف احتیاطی درخواست‌ها.

اگر قیمت آماده نیست، به‌جای نمایش قیمت قدیمی به‌عنوان قیمت لحظه‌ای، از عبارت «استعلام قیمت موقتاً در دسترس نیست» استفاده کن و ثبت سفارش قطعی را متوقف نگه دار.

## ۷. تفاوت نرخ واقعی و به‌روزرسانی دوره‌ای

- نماد رسمی: `GOLD_18_RLS`
- اندپوینت: `GET https://servix.cc/api/v1/assets/GOLD_18_RLS`
- کلید: **فقط در هدر** `X-API-Key`
- `quoteUnit=RLS`: ریال ایران برای یک گرم ۱۸ عیار
- `value`: نرخ (بر ۱۰ تقسیم و به تومان تبدیل می‌شود)
- `businessTime`: زمان اعلام نرخ در منبع (باید به‌روز باشد)

در سیستم حاضر **خواندن هر ۳۰ دقیقه به معنی تازه‌شدن قطعی دادهٔ بازار نیست**. اگر سرویکس رکورد جدیدی نداشته باشد، نرخ قبلی فقط تا زمان اعتبار خودش قابل استفاده است؛ پس از آن سفارش‌گیری متوقف می‌شود.

اگر سرویکس `429 DAILY_LIMIT_EXCEEDED` بدهد، Worker برای احتیاط به مدت **۲۴ ساعت از همان نقطه** درخواست‌های دیگر Servix را متوقف می‌کند. این **زمان ریست رسمی سهمیه نیست**؛ Servix زمان دقیق ریست را در راهنمای عمومی اعلام نکرده است. خطاهای احراز هویت و اطلاعات قدیمی را نیز بدون ساختن نرخ جایگزین ثبت می‌کنیم.

## ۸. برای فروش واقعی هنوز باید تکمیل شود

- تست واقعی با کلید خودتان روی هاست و PostgreSQL، و تست هم‌زمانی و خطا در worker؛
- تأیید مستقل نرخ سرویس و مجاز بودن نوع استفاده؛
- سیاست مالیات / ارسال تأییدشده و فرآیندهای قانونی؛
- اتصال پیامک، پرداخت معتبر و نظارت/هشدار خطا؛
- اتصال فرانت‌اند V5 به API عمومی Django و ورود اطلاعات واقعی محصولات.

> شرایط استفادهٔ Servix صحت و به‌موقع‌بودن نرخ برای معاملات را تضمین نمی‌کند؛ برای فروش طلا این سامانه باید همراه با نظارت و قواعد ریسک فروشگاه استفاده شود.
